    NLP pipeline

    Spoken language understanding + dialogue state for English, Hindi and Tamil. Numbers in answers come only from the weather API.

    Stages

    1. ASR (optional) — Whisper maps waveform → text. Language can be forced (en / hi / ta) to cut language-ID errors on short clips.
    2. Language ID — native scripts (Devanagari / Tamil / Latin) first; romanized Hindi/Tamil cues (mein, mosam, mazhai…) override English when the text is Latin-only.
    3. Dialect ID — char n-gram TF-IDF (1–5) + word n-grams + linear SVM, script-gated so a Hindi utterance is never scored as Kongu. Labels: Bhojpuri, Haryanvi, Bambaiya · Chennai, Kongu, Madurai, Nellai.
    4. Joint NLU — MuRIL encoder with a learned mix of all layers (final LayerNorm on the public checkpoint is near-degenerate). Heads: intent (MASSIVE) + BIO slots (place, date, time-of-day, weather descriptor).
    5. Canonicalisation — surface forms → language-independent symbols (gazetteer places, relative dates, rain/temp/…). Dialect lexicons feed the same symbols.
    6. Dialogue state — blackboard carry-over: elliptical follow-ups inherit intent/slots across language switches. Joint goal accuracy collapses without this.
    7. Tool + grounded NLG — Open-Meteo payload only; templates lexicalise WMO codes and dates per reply language.
    8. Travel time — “how long to get there” keeps the place from the previous turn in any language. Road distance (driving route, or haversine × 1.35) is stretched by rain, storms, fog, snow or wind. Say “I'm in Delhi” to set the start, or allow location.
    9. Spoken form + TTS — numbers/symbols → words in the question language; optional lexicon dialect wording (voice stays en/hi/ta neural TTS).

    Dialect train/test rewrites are synthetic unless you add native-speaker rows under data/dialect/collected/.
